Java 异常处理 ​

异常处理是 Java 保证程序健壮性的核心机制。本文将详细讲解异常体系、try-catch-finally 语法、自定义异常以及异常处理的最佳实践。

核心概念 ​

类型说明处理方式
Error严重错误，不应捕获通常不处理
RuntimeException运行时异常，可避免选择性处理
Exception（非运行时）受检异常必须处理

基础语法 ​

try-catch-finally ​

java
public void readFile(String path) {
    FileReader reader = null;
    try {
        reader = new FileReader(path);
        int data;
        while ((data = reader.read()) != -1) {
            System.out.print((char) data);
        }
    } catch (FileNotFoundException e) {
        // 捕获特定异常
        System.err.println("文件不存在: " + path);
    } catch (IOException e) {
        // 捕获更通用的异常
        System.err.println("读取文件失败: " + e.getMessage());
    } finally {
        // 无论是否异常都会执行（可选）
        if (reader != null) {
            try {
                reader.close();
            } catch (IOException e) {
                System.err.println("关闭文件失败");
            }
        }
    }
}

多异常捕获 ​

java
public void processFile(String path) {
    try {
        // 可能抛出多种异常的代码
        parseFile(path);
    } catch (FileNotFoundException | NoSuchMethodException e) {
        // Java 7+：捕获多个异常类型
        handleError(e);
    } catch (Exception e) {
        // 捕获所有其他异常
        logError(e);
    }
}

try-with-resources ​

java
// Java 7+ 自动关闭资源（实现 AutoCloseable 接口）
public String readFile(String path) throws IOException {
    // 资源会自动关闭，无需 finally
    try (BufferedReader reader = new BufferedReader(new FileReader(path))) {
        return reader.readLine();
    }
}

// 自定义 AutoCloseable 资源
public class MyResource implements AutoCloseable {
    @Override
    public void close() throws Exception {
        System.out.println("资源已关闭");
    }
    
    public void doWork() {
        System.out.println("执行工作");
    }
}

// 使用
try (MyResource resource = new MyResource()) {
    resource.doWork();
}

受检异常与非受检异常 ​

受检异常（Checked Exception） ​

必须显式处理（try-catch 或 throws 声明）：

java
// 方式一：try-catch 处理
public void loadConfig() {
    try {
        FileInputStream fis = new FileInputStream("config.properties");
        // ...
    } catch (IOException e) {
        logger.error("加载配置失败", e);
    }
}

// 方式二：throws 声明（交给调用者处理）
public void loadConfig() throws IOException {
    FileInputStream fis = new FileInputStream("config.properties");
    // ...
}

// 方式三：包装为非受检异常
public void loadConfig() {
    try {
        FileInputStream fis = new FileInputStream("config.properties");
    } catch (IOException e) {
        throw new UncheckedIOException("加载配置失败", e);
    }
}

非受检异常（Unchecked Exception） ​

继承 RuntimeException，不强制处理：

java
public String getValue(Map<String, String> map, String key) {
    // 可能抛出 NullPointerException
    return map.get(key).toUpperCase();
    
    // 应使用防御性编程
    String value = map.get(key);
    if (value == null) {
        throw new IllegalArgumentException("Key not found: " + key);
    }
    return value.toUpperCase();
}

自定义异常 ​

创建自定义异常类 ​

java
// 受检异常
public class BusinessException extends Exception {
    private final int code;
    
    public BusinessException(String message) {
        super(message);
        this.code = 500;
    }
    
    public BusinessException(int code, String message) {
        super(message);
        this.code = code;
    }
    
    public BusinessException(String message, Throwable cause) {
        super(message, cause);
        this.code = 500;
    }
    
    public int getCode() {
        return code;
    }
}

// 非受检异常
public class ValidationException extends RuntimeException {
    private final String fieldName;
    
    public ValidationException(String fieldName, String message) {
        super(message);
        this.fieldName = fieldName;
    }
    
    public ValidationException(String message, Throwable cause) {
        super(message, cause);
        this.fieldName = "unknown";
    }
    
    public String getFieldName() {
        return fieldName;
    }
}

使用自定义异常 ​

java
public class UserService {
    
    public User getUserById(Long id) throws BusinessException {
        if (id == null || id <= 0) {
            throw new ValidationException("id", "ID 必须大于 0");
        }
        
        User user = userRepository.findById(id);
        if (user == null) {
            throw new BusinessException(404, "用户不存在: " + id);
        }
        
        return user;
    }
    
    public void registerUser(User user) {
        // 参数校验
        if (user.getEmail() == null || !isValidEmail(user.getEmail())) {
            throw new ValidationException("email", "邮箱格式不正确");
        }
        
        // 业务校验
        if (userRepository.existsByEmail(user.getEmail())) {
            throw new BusinessException(409, "邮箱已被注册");
        }
        
        // 保存用户
        userRepository.save(user);
    }
}

异常的传递与处理 ​

异常传播机制 ​

java
public class ExceptionPropagation {
    
    // 最底层：可能抛出异常
    public void readData() throws IOException {
        FileInputStream fis = new FileInputStream("data.txt");
        fis.read();
        // 如果发生异常，向上抛出
    }
    
    // 中间层：可以选择处理或继续抛出
    public void processData() throws IOException {
        readData();  // 异常继续向上传播
    }
    
    // 最顶层：最终处理
    public void start() {
        try {
            processData();
        } catch (IOException e) {
            // 记录日志
            log.error("处理数据失败", e);
            
            // 友好提示
            showError("数据加载失败，请稍后重试");
        }
    }
}

异常链与包装 ​

java
public class ExceptionChaining {
    
    // 保留原始异常信息
    public void processOrder(Long orderId) throws OrderProcessingException {
        try {
            validateOrder(orderId);
            paymentService.charge(orderId);
        } catch (PaymentException e) {
            // 包装为更高层的异常，但保留原始原因
            throw new OrderProcessingException(
                "订单支付失败: " + orderId, 
                e  // 原始异常作为 cause
            );
        }
    }
    
    // 查看异常链
    public void handleException(Exception e) {
        Throwable cause = e.getCause();
        while (cause != null) {
            System.out.println("Caused by: " + cause.getMessage());
            cause = cause.getCause();
        }
    }
}

try-catch 的高级用法 ​

try-catch-return 执行顺序 ​

java
public class ReturnOrder {
    
    // 示例一：finally 中无 return
    public int testReturn1() {
        int x = 1;
        try {
            return x;  // 保存返回值 1
        } finally {
            x++;  // 修改不影响已保存的返回值
        }
    }
    // 返回 1
    
    // 示例二：finally 中有 return
    public int testReturn2() {
        int x = 1;
        try {
            return x;  // 准备返回 1
        } finally {
            x++;
            return x;  // 覆盖为 2
        }
    }
    // 返回 2
    
    // 示例三：catch 块
    public int testReturn3() {
        int x = 1;
        try {
            int y = 0;
            return x / y;  // 抛出异常
        } catch (Exception e) {
            x = 2;
            return x;  // catch 中返回 2
        } finally {
            x++;  // 仍然执行
        }
    }
    // 返回 2（finally 的 x++ 不影响）
}

try-catch-finally 与 return 总结 ​

场景try 中 returnfinally 执行最终返回
正常执行return 5✅ 执行5
finally 改变变量return x (x=5)x=65（保存的原值）
finally 有 returnreturn 5return 66（被覆盖）
catch 中 return异常✅ 执行catch 中的值

异常处理最佳实践 ​

原则一：不要忽略异常 ​

java
// ❌ 错误：空 catch 块
try {
    riskyOperation();
} catch (Exception e) {
    // 什么都不做！
}

// ✅ 正确：至少记录日志
try {
    riskyOperation();
} catch (Exception e) {
    log.error("操作失败", e);
    // 或向上抛出
    throw new RuntimeException("操作失败", e);
}

原则二：不要用异常控制流程 ​

java
// ❌ 错误：用异常做逻辑判断
try {
    int value = Integer.parseInt(str);
    processValue(value);
} catch (NumberFormatException e) {
    // 不是数字，跳过
}

// ✅ 正确：先检查再处理
if (isNumeric(str)) {
    int value = Integer.parseInt(str);
    processValue(value);
}

原则三：提供有用的错误信息 ​

java
// ❌ 错误：无意义的错误信息
catch (SQLException e) {
    throw new Exception("Error");
}

// ✅ 正确：包含上下文信息
catch (SQLException e) {
    throw new DataAccessException(
        "查询用户失败, userId=" + userId + ", sql=" + sql,
        e
    );
}

原则四：精确捕获异常 ​

java
// ❌ 错误：捕获过于宽泛
catch (Exception e) {
    // 可能掩盖了非预期的错误
}

// ✅ 正确：捕获具体异常
catch (FileNotFoundException e) {
    // 处理文件不存在
} catch (IOException e) {
    // 处理其他 IO 错误
}

原则五：使用 try-with-resources ​

java
// ❌ 错误：手动关闭（容易遗漏）
InputStream is = null;
try {
    is = new FileInputStream("file.txt");
    process(is);
} catch (IOException e) {
    // ...
} finally {
    if (is != null) {
        try { is.close(); } catch (IOException ignored) {}
    }
}

// ✅ 正确：自动关闭
try (InputStream is = new FileInputStream("file.txt")) {
    process(is);
} catch (IOException e) {
    log.error("处理文件失败", e);
}

原则六：日志记录 ​

java
// 分层异常处理策略
public class GlobalExceptionHandler {
    
    private static final Logger log = LoggerFactory.getLogger(GlobalExceptionHandler.class);
    
    // Controller 层：捕获并返回友好信息
    @ExceptionHandler(BusinessException.class)
    public ResponseEntity<?> handleBusinessException(BusinessException e) {
        log.warn("业务异常: {}", e.getMessage());
        return ResponseEntity
            .status(HttpStatus.BAD_REQUEST)
            .body(new ErrorResponse(e.getCode(), e.getMessage()));
    }
    
    // Service 层：记录详细日志
    public void processRequest(Request req) {
        try {
            validate(req);
            execute(req);
        } catch (ValidationException e) {
            log.warn("参数校验失败: field={}, msg={}", e.getFieldName(), e.getMessage());
            throw e;  // 继续向上抛出
        } catch (Exception e) {
            log.error("处理请求失败, req={}", req, e);
            throw new BusinessException("系统繁忙，请稍后重试", e);
        }
    }
}

资源关闭 ​

java
// try-with-resources 自动关闭
public List<String> readLines(String path) throws IOException {
    try (Stream<String> lines = Files.lines(Paths.get(path))) {
        return lines.filter(line -> !line.isEmpty())
                    .collect(Collectors.toList());
    }
}

// 多个资源
public void copyFile(String source, String dest) throws IOException {
    try (InputStream in = new FileInputStream(source);
         OutputStream out = new FileOutputStream(dest)) {
        byte[] buffer = new byte[8192];
        int bytesRead;
        while ((bytesRead = in.read(buffer)) != -1) {
            out.write(buffer, 0, bytesRead);
        }
    }
}
