# JVM 内存模型与垃圾回收

JVM 内存模型和垃圾回收机制是 Java 性能优化的核心知识。本文将深入讲解 JVM 的内存结构、对象创建过程、GC 算法以及常用的垃圾回收器。

| 区域 | 类型 | 说明 | 异常 |

| 堆 (Heap) | 共享 | 存储对象实例和数组 | OutOfMemoryError |
| 方法区 | 共享 | 存储类信息、常量、静态变量 | OutOfMemoryError |
| 元空间 (JDK8+) | 共享 | 替代永久代，使用本地内存 | OutOfMemoryError |
| 虚拟机栈 | 私有 | 存储栈帧（局部变量、操作数栈） | StackOverflowError |

| 程序计数器 | 私有 | 记录字节码执行位置 | 无 |

## 垃圾回收概述

### 什么是垃圾

不再被任何引用指向的对象就是垃圾，需要被回收释放内存。

```java
public class GarbageExample {
    
    public void createGarbage() {
        Object obj1 = new Object();
        
        // 情况一：引用置空
        obj1 = null;  // obj1 成为垃圾
        
        // 情况二：引用超过作用域
        if (true) {
            Object obj2 = new Object();
        }  // obj2 成为垃圾
        
        // 情况三：相互引用但外部无引用
        A a = new A();
        B b = new B();
        a.b = b;
        b.a = a;
        a = null;
        b = null;
        // a 和 b 互相引用，但外部已无引用，都是垃圾
    }
    
    class A { B b; }
    class B { A a; }
}
```

## 垃圾回收算法

### 标记-清除算法（Mark-Sweep）

```
阶段一：标记
  - 从 GC Roots 出发，标记所有存活对象
  
阶段二：清除
  - 遍历整个堆，清除未标记的对象

┌─────────────────────────────────────────────────┐
│              标记前                               │
│  ┌─────┬─────┬─────┬─────┬─────┬─────┐         │
│  │ A   │ B   │ C   │ D   │ E   │ F   │         │
│  └─────┴─────┴─────┴─────┴─────┴─────┘         │
│  全部都是未标记状态                                │
└─────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────┐
│              标记后                               │
│  ┌─────┬─────┬─────┬─────┬─────┬─────┐         │
│  │ A ✓ │ B ✓ │ C ✗ │ D ✓ │ E ✗ │ F ✓ │         │
│  └─────┴─────┴─────┴─────┴─────┴─────┘         │
│  C 和 E 不可达，标记为垃圾                         │
└─────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────┐
│              清除后                               │
│  ┌─────┬─────┬─────┬─────┬─────┬─────┐         │
│  │ A   │ B   │ ███ │ D   │ ███ │ F   │         │
│  └─────┴─────┴─────┴─────┴─────┴─────┘         │
│  C 和 E 被清除，产生内存碎片                       │
└─────────────────────────────────────────────────┘

优点：实现简单
缺点：产生内存碎片
```

### 复制算法（Copying）

```
将堆内存分为两块：From 空间和 To 空间

GC 过程：
1. 从 From 空间出发，标记存活对象
2. 将存活对象复制到 To 空间
3. 交换 From 和 To 的角色
4. 清空原 From 空间

┌─────────────────────┐
│       堆内存          │
│  ┌─────────┬───────┐│
│  │ From    │  To   ││
│  │ 空间    │ 空间   ││
│  └─────────┴───────┘│
└─────────────────────┘

GC 前:
┌─────────────────────┬─────────────────────┐
│      From 空间       │       To 空间        │
│  ┌─────┬─────┬─────┐│  ┌─────────────────┐│
│  │ A   │ B   │ C   ││  │                 ││
│  └─────┴─────┴─────┘│  └─────────────────┘│
└─────────────────────┴─────────────────────┘

GC 后:
┌─────────────────────┬─────────────────────┐
│      From 空间       │       To 空间        │
│  ┌─────────────────┐│  ┌─────┬─────┬─────┐│
│  │                 ││  │ A   │ C   │ ... ││
│  └─────────────────┘│  └─────┴─────┴─────┘│
└─────────────────────┴─────────────────────┘
(已交换角色，From 被清空，To 变为新的 From)

优点：无内存碎片，效率高
缺点：可用内存减半
应用：新生代（Eden + Survivor0 + Survivor1）
```

### 标记-整理算法（Mark-Compact）

```
阶段一：标记
  - 从 GC Roots 出发，标记所有存活对象

阶段二：整理
  - 将存活对象向一端移动
  - 更新对象引用指针
  - 清除边界外的内存

┌─────────────────────────────────────────────────┐
│              整理前                               │
│  ┌─────┬─────┬─────┬─────┬─────┬─────┐         │
│  │ A   │ ███ │ B   │ ███ │ C   │ ███ │         │
│  └─────┴─────┴─────┴─────┴─────┴─────┘         │
│  A、B、C 存活，其他为垃圾                          │
└─────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────┐
│              整理后                               │
│  ┌─────┬─────┬─────┬─────────────────────────┐   │
│  │ A   │ B   │ C   │                         │   │
│  └─────┴─────┴─────┴─────────────────────────┘   │
│  存活对象向一端移动，无碎片                          │
└─────────────────────────────────────────────────┘

优点：无内存碎片
缺点：移动对象开销大
应用：老年代
```

### 分代收集算法（Generational）

```
根据对象存活周期将内存分为不同代，各代采用不同回收算法

新生代：对象朝生夕灭，存活率低
  - 使用复制算法
  - Eden (8) : Survivor0 (1) : Survivor1 (1)
  
老年代：对象存活率高
  - 使用标记-清除或标记-整理算法
  
对象晋升：
  - 对象在新生代每经历一次 GC 存活，年龄 +1
  - 年龄达到阈值（默认 15）晋升到老年代
  - 大对象直接进入老年代
  - 空间分配担保：Survivor 空间不足时，部分对象直接晋升
```

## 垃圾回收器

### 垃圾回收器分类

```

│  GC 器：具体实现（工程实现）                               │

└─────────────────────────────────────────────────────────┘
```

### 常见 GC 器

| GC 器 | 类型 | 算法 | 适用场景 |
|-------|------|------|----------|
| Serial | 单线程 | 复制/标记-整理 | 客户端/小内存 |
| ParNew | 多线程 | 复制 | 配合 CMS |
| Parallel Scavenge | 多线程 | 复制 | 吞吐量优先 |
| CMS | 并发 | 标记-清除 | 低延迟 |
| G1 | 并发 | 分区收集 | JDK 9+ 默认 |
| Shenandoah | 并发 | Brooks Pointer | 低延迟 |
| ZGC | 并发 | 着色指针 |超低延迟(JDK 11+) |

### G1 收集器详解

```
G1 (Garbage-First) 将堆分为多个 Region

┌─────────────────────────────────────────────────────────┐
│                      G1 内存布局                         │
│                                                           │
│  ┌─────────────────────────────────────────────────────┐ │
│  │                        堆内存                        │ │
│  │  ┌────┬────┬────┬────┬────┬────┬────┬────┬────┐    │ │
│  │  │R0  │R1  │R2  │R3  │R4  │R5  │R6  │R7  │R8  │    │ │
│  │  └────┴────┴────┴────┴────┴────┴────┴────┴────┘    │ │
│  │  每个 Region 大小相等（1-32MB）                      │ │
│  │                                                     │ │
│  │  Region 类型:                                       │ │
│  │  ├── Free: 空闲 Region                              │ │
│  │  ├── Eden: 新生代 Eden                              │ │
│  │  ├── Survivor: 新生代 Survivor                      │ │
│  │  ├── Old: 老年代                                    │ │
│  │  └── Humongous: 巨型对象 Region                     │ │
│  └─────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────┘

G1 GC 过程：
1. 初始标记（STW）
   - 标记 GC Roots 直接引用的对象
   
2. 并发标记
   - 并发遍历整个堆，标记存活对象
   - 可被中断
   
3. 最终标记（STW）
   - 处理 SATB 记录的引用变化
   
4. 筛选回收
   - 按 Region 回收价值排序
   - 优先回收垃圾多的 Region
   - 复制存活对象到新 Region
```

## 对象的生命周期

### 对象的死亡

```java
// 对象从出生到死亡的过程

public class ObjectLifecycle {
    
    // 阶段 1: 对象创建
    // - 类加载检查
    // - 分配内存
    // - 初始化
    // - 构造方法执行
    
    public void createObject() {
        Object obj = new Object();
        // 对象出生
    }
    
    // 阶段 2: 对象存活
    // - 被引用时存活
    // - 可以被访问和使用
    
    public void useObject(Object obj) {
        System.out.println(obj.toString());
    }
    
    // 阶段 3: 成为垃圾
    // - 引用消失
    // - 不可达
    
    public void becomeGarbage() {
        Object obj = new Object();
        obj = null;  // 成为垃圾
    }
    
    // 阶段 4: 对象死亡
    // - GC 回收
    // - finalize() 被调用（如果覆盖了）
    // - 内存被释放
    
    public class MyObject {
        @Override
        protected void finalize() throws Throwable {
            // 不推荐使用，可能导致内存泄漏
            super.finalize();
        }
    }
}
```

### finalize 方法

```java
public class FinalizeExample {
    
    // finalize() 已在 JDK 9 中被标记为过时
    // 不推荐使用
    
    public class Resource {
        private boolean closed = false;
        
        // 推荐方式：try-with-resources + AutoCloseable
        public void useResource() {
            try (Resource res = new Resource()) {
                // 使用资源
            } catch (Exception e) {
                // 处理异常
            }
        }
        
        // 不推荐方式：finalize()
        @Override
        protected void finalize() throws Throwable {
            if (!closed) {
                // 可能导致：
                // 1. GC 延迟
                // 2. 对象复活
                // 3. 资源泄漏
                System.err.println("资源未正确关闭");
            }
            super.finalize();
        }
    }
    
    // 推荐使用 Cleaner（JDK 9+）
    public class CleanableResource implements AutoCloseable {
        private static final Cleaner cleaner = Cleaner.create();
        
        private final Cleaner.Cleanable cleanable;
        
        public CleanableResource() {
            // 注册清理动作
            this.cleanable = cleaner.register(this, () -> {
                // 清理逻辑
            });
        }
        
        @Override
        public void close() {
            cleanable.clean();
        }
    }
}
```
