# 10-Docker环境变量与Config文件注入全攻略

应用运行时往往需要外部配置，而这些配置不应该写死在代码里。数据库地址、端口号、接口密钥、环境标识、日志级别等信息，通常都应该由运行时决定。Docker 提供了两种常见方式来管理这类配置：环境变量和配置文件挂载。

环境变量是最常见、也最容易管理的一种方式。你可以在启动容器时使用 `-e` 参数传入变量，比如 `NODE_ENV=production` 或 `PORT=3000`。它适合管理简单、离散、敏感度较高的配置，例如密钥、账号、服务模式等。相较于硬编码，环境变量让配置和代码解耦，部署时能更灵活地切换运行状态。

配置文件挂载则适合承载更复杂、结构更清晰的数据。比如 JSON、YAML、Nginx 配置、数据库配置文件等，可以直接通过挂载的方式交给容器使用。这样配置文件可以在宿主机上维护，容器内按预期读取，既方便调试，也方便不同环境切换。

在工程实践中，最推荐的做法是把敏感配置放到环境变量里，把结构化配置放到配置文件中。这样能够兼顾安全性和可维护性。一个常见错误是把所有配置都写死在镜像里，这会让镜像不够通用，也让环境切换变得更困难。

配置管理不是“加几个变量”那么简单，它是把应用的可变部分从代码中剥离出来，交由运行环境决定。真正成熟的 Docker 使用方式，通常都遵循这个原则。
