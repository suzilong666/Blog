# 15-容器监控-cAdvisor-Prometheus-Grafana

## 引言

随着容器数量增加，单靠日志和人工巡检已经无法掌握系统健康。cAdvisor + Prometheus + Grafana 已成为容器监控的经典组合，可以让你从“感觉系统还行”变成“数据告诉我哪里不对”。

本篇文章介绍这套组合的角色分工、典型指标、实战搭建和落地建议。

## 监控为什么是容器化环境的基础

容器环境的特点是：

- 实例数量多；
- 启停频繁；
- 资源隔离复杂；
- 服务间依赖紧密。

这意味着你需要持续采集资源、性能与健康指标，而不是靠一次性排查。

## 组件角色

### cAdvisor

- 负责采集容器层级的资源使用指标；
- 关注 CPU、内存、磁盘、网络等容器级别指标；
- 通常部署在每个节点上。

### Prometheus

- 负责抓取指标并存储；
- 提供强大的查询语言 PromQL；
- 支持告警与数据持久化。

### Grafana

- 负责可视化展示；
- 将 Prometheus 指标转成仪表盘；
- 适合构建运营、研发、SRE 的观察面板。

## 实战搭建概览

典型流程为：

1. 在每个宿主机上运行 cAdvisor；
2. Prometheus 定期抓取 cAdvisor 指标；
3. Grafana 访问 Prometheus 数据源；
4. 构建容器监控仪表盘。

## 关键指标

### 容器资源指标

- CPU 使用率；
- 内存占用；
- 磁盘 I/O；
- 网络流量；
- 容器重启次数。

### 服务健康指标

- `up` 状态；
- HTTP 接口响应时间；
- 错误率；
- 队列长度。

这些指标能帮助你迅速定位“资源瓶颈”“异常服务”“边界故障”。

## 常见落地实践

### 1. 先从关键服务开始

不必一开始把所有容器都监控起来。优先监控核心服务和关键节点，例如数据库、网关、调度服务。

### 2. 结合告警

为异常指标设置告警，例如：

- CPU 持续高于 80%；
- 内存使用接近限制；
- 容器重启次数异常；
- 健康检查失败。

### 3. 设计仪表盘

推荐构建三个维度仪表盘：

- 单节点资源面板；
- 服务健康面板；
- 业务流量面板。

### 4. 观察容器生命周期

监控不仅看当前指标，还要关注趋势。容器启动、停止、重启的频率往往比单次峰值更重要。

## 工程化建议

- 将监控配置纳入版本控制；
- 在新容器上线前先验证监控采集是否正常；
- 使用服务发现自动注册 cAdvisor/Prometheus 抓取目标；
- 定期评估告警阈值，避免告警疲劳。

## 常见误区

- 认为“日志收集就是监控”。日志是事后分析，监控是实时预警；
- 认为“监控太复杂，先不做”。容器化环境越大，越需要早期布局；
- 只看整体指标，不看容器粒度。单个容器异常往往是故障起点。

## 小结

容器监控不是“可选项”，而是现代容器平台的基础设施。cAdvisor、Prometheus 和 Grafana 的组合，能让你把容器运行状态从“感觉上正常”转成“数据可观测”。把它作为容器工程化的一部分，能显著提升系统稳定性和运维效率。
