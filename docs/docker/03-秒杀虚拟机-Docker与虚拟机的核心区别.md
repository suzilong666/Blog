# 03-秒杀虚拟机-Docker与虚拟机的核心区别

Docker 和虚拟机经常被放在一起讨论，但它们的底层思路并不一样。虚拟机的目标，是模拟一整套硬件环境，再在其上运行完整操作系统；Docker 的目标，则是让应用以更轻量的方式运行在一个隔离环境里。二者都能提供隔离，但它们的适用场景并不相同。

虚拟机通常会虚拟出 CPU、内存、磁盘、网卡等硬件资源，再安装一套完整的操作系统。这样做的优点是隔离性很强，兼容性也高，适合运行不同的操作系统和做系统级测试。缺点则是显而易见的：启动慢、资源消耗大、镜像体积大，维护成本也高。

Docker 的设计思路更轻量。它不是虚拟整套系统，而是共享宿主机的内核，在上面运行独立的容器。这个设计让它具有启动快、占用资源少、部署高效的优势。对于现代 Web 应用、微服务、持续部署和开发环境标准化来说，Docker 更符合当前工程需求。

更准确地说，虚拟机解决的是“完整系统级别的隔离”，而 Docker 解决的是“应用级别的轻量隔离”。前者重，后者轻；前者更适合复杂系统环境模拟，后者更适合快速交付和高效运维。两者不是简单的谁替代谁，而是不同场景下的不同工具。

所以，当你在做技术选型时，不应该把 Docker 视为“虚拟机的简化版”，而应该把它看成另一种更适合现代应用交付的运行方式。它更关注的是速度、便携性和工程效率，而不是完整系统模拟。
