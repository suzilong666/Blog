# 12-Docker依赖控制与Healthcheck最佳实践

服务启动成功，并不等于它已经真正可用。对于数据库、缓存、消息队列这类依赖组件来说，容器“已经启动”与“已经准备好接收请求”之间，往往存在一段很重要的过渡期。如果应用在这个阶段就开始初始化连接，往往会带来一连串异常：超时、失败重试、连接不上、启动回退等。

Docker 的 Healthcheck 机制，就是为了解决这种依赖控制问题。它允许你为容器定义检查命令，根据返回结果判断当前容器是否健康。只有当容器达到健康状态时，系统才会认为它可以继续提供服务。这个机制对服务编排和生产环境稳定性都非常重要。

健康检查的写法可以非常简单，也可以非常细化。常见的做法是让容器定期访问某个接口、检查某个端口或执行某个脚本。如果检查失败达到一定次数，容器就会被标记为不健康。这样一来，外部流量就不会被错误地引向一个尚未准备好的服务。

在实际项目中，Healthcheck 往往和 Compose 的依赖控制结合使用，效果更好。比如让 Web 服务等待数据库容器健康之后再启动，或者让网关只在后端服务健康时再转发请求。这类策略能显著减少启动顺序不合理带来的故障，让系统更稳。

很多团队在初期会忽略健康检查，觉得“容器启动了就算成功”。但真正稳定的线上系统，通常都需要显式地定义服务健康状态，而不是依赖猜测和运气。
