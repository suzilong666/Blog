# 19-Docker安全全景扫描-Rootless模式与镜像漏洞检测实战

## 引言

容器安全不是“把程序装进容器就安全”。它需要覆盖镜像构建、运行时权限、漏洞扫描和持续治理。

本篇文章从 Rootless 模式、镜像扫描、运行权限和安全实践四个维度，帮助你构建更稳妥的 Docker 安全体系。

## 1. 容器并非天然安全

容器提供隔离，但它仍共享宿主机内核。如果镜像中含有漏洞，或容器以 root 权限运行，就存在被攻击后破坏宿主机的风险。

安全风险常见于：

- 未审核的基础镜像；
- 过度开放权限；
- 暴露无关端口；
- 运行时凭证泄露；
- 不定期更新依赖。

## 2. Rootless 模式：降低特权风险

Rootless 模式让 Docker 守护进程和容器尽量以非 root 用户运行。

优点：

- 减少提权攻击面；
- 降低容器突破后的危害；
- 更符合最小权限原则。

配置示例（Linux）：

```bash
dockerd-rootless.sh
```

在生产环境，优先让容器内部进程使用非 root 用户：

```dockerfile
USER node
```

## 3. 镜像漏洞扫描

镜像往往是安全链条的起点。常见扫描工具包括：

- Docker Hub 安全扫描；
- Trivy；
- Clair；
- Anchore；
- Aqua。

扫描内容包括：

- 基础镜像漏洞；
- 应用依赖漏洞；
- 公开端口与运行命令；
- 证书与凭证泄露。

示例：

```bash
trivy image myapp:latest
```

## 4. 运行时安全实践

### 4.1 最小权限运行

- 使用 `USER` 设定非 root 用户；
- 不要在容器内安装调试工具；
- 使用 `--read-only` 让根文件系统只读；
- 对必要目录使用 `tmpfs` 或只读挂载。

### 4.2 端口与网络控制

- 只暴露必要端口；
- 使用防火墙和网络策略；
- 不要把容器直接曝露在公网上。

### 4.3 凭证管理

- 不要把密钥写入 Dockerfile；
- 使用 `docker secret`、环境变量或配置中心；
- 定期轮换凭证。

## 5. 持续安全治理

安全不是一次性任务，而是持续过程。

建议做法：

- 把镜像扫描作为 CI 阶段；
- 定期更新基础镜像和依赖；
- 监控异常行为；
- 建立安全事件响应流程。

## 6. 常见误区

- 认为容器隔离等于安全隔离；
- 只关注应用代码漏洞，不关注基础镜像漏洞；
- 觉得 Rootless 复杂就不做；
- 认为扫描一次就够。安全需要持续关注。

## 小结

Docker 安全要从“镜像安全”“运行时权限”“漏洞扫描”“持续治理”四个层面构建。Rootless 模式和镜像扫描是两个重要切入点，但最终的安全能力来自于“把安全纳入交付流程”，而不是偶尔做一次检查。
