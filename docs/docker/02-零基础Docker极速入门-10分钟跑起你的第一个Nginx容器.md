# 02-零基础Docker极速入门-10分钟跑起你的第一个Nginx容器

## 引言

对初学者来说，理解 Docker 最有效的方式不是直接从复杂应用入手，而是从一个经典的“镜像拉取、容器运行、端口映射”流程开始。Nginx 作为最常见的 Web 服务，在 10 分钟内就可以帮助你把 Docker 的运行机制看清楚。

## 为什么先从 Nginx 开始？

Nginx 具备以下特点：

- 容量小、启动快；
- 官方镜像已经预配置好运行环境；
- 服务端口固定，易于验证；
- 结果直观，访问即可确认是否成功。

它是最适合用来建立 Docker 思维模型的“第一课”。

## 关键流程：拉镜像、启动容器、访问服务

### 1. 拉取镜像

镜像可以理解为容器运行所依赖的基础模板。官方镜像已经把 Nginx 运行环境准备好了：

```bash
docker pull nginx
```

这一步完成后，你会在本机的镜像仓库中得到一个名为 `nginx` 的镜像。

### 2. 启动容器

接下来把镜像实例化成一个运行中的容器：

```bash
docker run -d --name my-nginx -p 8080:80 nginx
```

命令含义：

- `-d`：后台运行；
- `--name my-nginx`：指定容器名称，方便管理；
- `-p 8080:80`：将宿主机 8080 端口映射到容器内 80 端口；
- `nginx`：使用的镜像名称。

### 3. 访问页面

打开浏览器访问：

```text
http://localhost:8080
```

如果出现 Nginx 默认欢迎页，说明容器已经正常运行并对外暴露服务。

## 进一步验证与排查

常用命令：

```bash
docker ps
docker logs my-nginx
docker exec -it my-nginx /bin/sh
```

- `docker ps`：查看正在运行的容器；
- `docker logs`：查看容器日志；
- `docker exec`：进入容器内部查看运行环境。

如果页面无法访问，先确认容器是否启动、端口是否映射、端口是否被占用。

## 这个练习的价值

通过这个例子，你会把以下概念串联起来：

- 镜像是只读模板；
- 容器是镜像的运行实例；
- 端口映射是宿主机与容器通信的桥梁；
- 日志和交互命令是排查故障的第一手资料。

## 推荐的下一步

当你把 Nginx 启动起来后，建议继续练习：

- 停止并删除容器：`docker stop my-nginx && docker rm my-nginx`；
- 修改 Nginx 配置并重新挂载；
- 结合 `docker-compose` 启动一个 Nginx + 应用程序栈。

## 常见误区

- 误以为 Docker 只是“把程序装进盒子里”。实际上它构建的是“隔离运行时环境”；
- 误以为容器启动就足够。没有日志和访问验证，问题往往会被忽略；
- 误用端口映射。`-p` 的左侧是宿主机端口，右侧是容器端口。

## 小结

10 分钟跑通 Nginx，是学 Docker 最好的起点。这个过程让你理解 Docker 的基本使用方式，也为后续学习镜像构建、数据卷、网络和编排打下基础。
