# 08-Docker网络模型详解-Bridge-Host-Overlay

如果容器只是单独运行一个服务，它的价值有限；真正有意义的场景，是多个容器一起工作。Web 服务、数据库、缓存、消息队列，各自运行在不同容器中，彼此需要通信，这时候 Docker 的网络能力就变得至关重要。

最常见的网络模式是 Bridge。Bridge 模式适合单机上的多容器通信，容器会被分配一个私有 IP，并且可以通过容器名或 IP 与其他容器通信。它是本地开发和一般多容器应用最常用的网络方式。

Host 模式则更直接。它让容器共享宿主机网络栈，因此性能更高、网络透明度更强，但其代价是隔离性更弱。对于一些性能敏感、对网络环境要求较高的场景，Host 模式会更合适。

Overlay 模式更适合跨主机的容器通信。它可以把不同节点上的容器连成一个虚拟网络，适用于 Docker Swarm 或 Kubernetes 这类集群场景。对于分布式系统来说，Overlay 是非常关键的能力。

理解这些模式的关键不在于“记住名称”，而在于知道不同场景下应该优先选哪种方式。单机开发优先 Bridge，高性能场景可看 Host，跨节点集群则通常需要 Overlay。网络模型决定了容器之间的协作方式，而协作方式又决定了整个系统是否能稳定运行。
