# 07-Docker数据卷管理实战-持久化再也不怕

容器最容易被忽略的一点，是它的生命周期通常很短。容器被删除、重建或重新部署时，内部的数据往往也随之消失。对于数据库、日志文件、上传内容、配置文件这类内容来说，这会带来很现实的问题。没有持久化机制的容器，几乎很难支撑复杂应用长期稳定运行。

Docker 提供的数据卷，就是为了解决这个问题。数据卷本质上是一个独立于容器生命周期的存储区域。它可以确保容器重建后依然保留数据，也可以让多个容器共享同一份数据。这对于 MySQL、Redis、MongoDB 这类需要长期保存状态的服务尤其重要。

常见使用方式是先创建一个命名卷，再把这个卷挂载到容器内的目标目录，例如数据库数据目录。这样即使容器被删除，数据也不会丢失。除了命名卷，Docker 还支持宿主机目录挂载，这种方式在本地开发环境中也非常有用。

在工程实践中，最重要的不是“知道怎么挂载”，而是“知道哪些数据应该持久化、哪些数据应该随容器消失”。数据库文件、上传文件、日志文件和配置文件，通常都应该被单独管理；而临时编译产物、缓存和中间文件则更适合留在镜像内或容器内。这样既能保持部署简洁，也能让应用在升级和迁移时更加稳妥。
