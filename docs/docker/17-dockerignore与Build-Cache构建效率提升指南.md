# 17-dockerignore与Build-Cache构建效率提升指南

镜像构建的效率，往往是开发体验里最容易被忽略但又最影响日常节奏的一部分。大量构建上下文文件、无关缓存和错误的构建顺序，会让 Docker 构建时间越来越长，CI 流水线越来越慢。对于频繁迭代的项目来说，这种低效会迅速累积成明显的成本。

`.dockerignore` 的作用，是在构建前告诉 Docker 哪些文件不需要进入构建上下文。像 `node_modules`、日志目录、临时文件、编译产物和本地缓存，这些内容通常都不应该被打包进去。减少构建上下文大小，不仅能缩短构建时间，还能降低发送和复制的开销。

Build Cache 的机制则是另一个关键点。Docker 会缓存之前已经完成的构建步骤，只要前面步骤没有变化，后续步骤就能复用缓存，而不需要重新执行。也就是说，Dockerfile 的写法、文件组织方式以及构建顺序，都会直接影响缓存命中率。

较好的实践是把依赖安装和源码复制分开。先复制依赖描述文件，执行安装，再复制业务代码，这样只要依赖文件没有变化，安装步骤就能复用缓存。另一个常见优化是避免把大文件和生成文件放进构建上下文。构建性能优化的本质，不是简单地“换一台更快的机器”，而是让构建过程更合理、更有针对性。
