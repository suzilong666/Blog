# 13-Docker-Swarm-从零搭建生产可用的高可用容器集群

## 引言

当单机 Docker 不能满足可用性或扩展性要求时，集群化部署成为必然。Docker Swarm 是 Docker 官方提供的一种轻量编排方案，适合从单机容器部署平滑过渡到多节点高可用集群。

本篇文章讲清 Swarm 的核心概念、基本搭建流程、生产实践与常见注意事项。

## 1. Swarm 是什么？

Docker Swarm 是一种集群模式，通过管理节点和工作节点，把多台主机组织成一个统一的集群。它支持：

- 服务副本；
- 负载均衡；
- 滚动更新；
- 服务发现；
- Overlay 网络。

与 Kubernetes 相比，Swarm 更轻量、入门更快捷，适合中小规模业务或容器编排的起步阶段。

## 2. Swarm 基本概念

- 管理节点（Manager）：负责集群控制面、调度和状态管理；
- 工作节点（Worker）：负责运行容器服务实例；
- 服务（Service）：定义要运行的容器镜像、副本数、网络等；
- 任务（Task）：服务的具体实例。

## 3. 从零搭建 Swarm

### 初始化 Swarm

在第一台主机上执行：

```bash
docker swarm init --advertise-addr <MANAGER-IP>
```

### 加入工作节点

在其他主机上执行：

```bash
docker swarm join --token <WORKER-TOKEN> <MANAGER-IP>:2377
```

### 查看节点状态

```bash
docker node ls
```

## 4. 部署服务

使用 `docker service create` 创建服务：

```bash
docker service create --name myapp --replicas 3 -p 80:80 nginx:latest
```

这会在集群中启动 3 个容器副本，并启用内部负载均衡。

## 5. 生产实践建议

### 5.1 节点角色规划

- 生产环境最好至少 3 个管理节点；
- 工作节点与管理节点分离；
- 使用专用节点运行持久化服务或高 IO 服务。

### 5.2 网络与存储

- 使用 Overlay 网络实现跨节点通信；
- 对持久化数据使用共享存储或外部卷插件；
- 避免把本地绑定卷作为生产级存储。

### 5.3 健康检查与更新策略

- 使用 `--update-parallelism` 和 `--update-delay` 进行滚动更新；
- 结合 `HEALTHCHECK` 确保仅健康实例对外提供服务；
- 设置服务重启策略。

### 5.4 监控与告警

- 监控节点资源、服务状态、任务重启；
- 关注 Overlay 网络、存储延迟、容器重启频率。

## 6. 什么时候选择 Swarm

适合：

- 需要快速搭建多节点集群；
- 业务规模适中；
- 团队希望先打好集群基础再考虑更复杂编排平台。

不适合：

- 需要复杂自定义调度；
- 追求云原生生态的深度集成；
- 需要大规模、多租户、多集群管理。

## 7. 常见误区

- 认为 Swarm 是“生产就能用所有场景”。它适合轻量级场景，但不是万能；
- 认为加入节点后就万事大吉。集群运维、升级、备份和存储仍然需要设计；
- 认为 Swarm 不需要监控。它同样需要监控节点、网络和服务状态。

## 小结

Docker Swarm 是从单机容器走向高可用集群的实用路径。它的优势是上手快、运维简洁，但要真正生产可用，仍需规划节点、网络、存储和监控。对于希望稳步过渡到集群化的团队，Swarm 是一个值得尝试的选择。
