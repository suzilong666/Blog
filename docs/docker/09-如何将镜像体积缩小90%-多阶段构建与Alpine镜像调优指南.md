# 09-如何将镜像体积缩小90%-多阶段构建与Alpine镜像调优指南

镜像体积并不是一个纯粹的“体积问题”，它直接影响构建速度、拉取时间、缓存命中率以及部署效率。一个过大的镜像会让 CI 流水线变慢，应用容器启动更慢，网络传输也更重。因此，镜像瘦身不只是为了看起来更干净，而是为了让整个交付链路更高效。

镜像变大的原因通常不止一个。常见问题包括基础镜像本身过大、安装了不必要的依赖、构建过程中保留了编译缓存和临时文件、或者把日志和生成产物也一并打进镜像。很多时候，开发者只把“能运行”作为目标，却从来没有认真审视镜像是否过于臃肿。

多阶段构建，是一种非常典型的优化手段。它允许你在构建阶段使用更大的环境安装依赖、执行编译和打包，但在最终阶段只保留运行所需的产物。这样最终镜像中就不会包含构建工具链、缓存文件和无关依赖，体积会显著下降。

Alpine 镜像则是另一种常见路径。它用非常轻量的基础系统来支撑应用运行，适合把镜像体积压到极小。但它也有自身的兼容性特点，尤其在 libc、系统包和依赖行为上，和更完整的发行版有所不同。所以，使用轻量镜像时，必须同时关注稳定性和兼容性。

镜像优化的核心，不是盲目追求数字，而是找到一个最优的平衡：既要尽量小，又要保证应用稳定运行。这才是构建高质量容器镜像的正确方向。
