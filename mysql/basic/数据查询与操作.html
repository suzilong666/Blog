数据查询与操作 ​

一、单表查询详解 ​

1.1 基本查询 ​

单表查询是指只涉及一张表的 SELECT 语句，是最基础也是最常用的查询类型。

sql
-- 查询所有列
SELECT * FROM employees;

-- 查询指定列
SELECT id, first_name, last_name, salary FROM employees;

-- 使用别名
SELECT
    first_name AS '名',
    last_name AS '姓',
    CONCAT(first_name, ' ', last_name) AS '姓名',
    salary * 12 AS '年薪'
FROM employees;

1.2 条件查询 ​

sql
-- 等值查询
SELECT * FROM employees WHERE department_id = 10;

-- 范围查询
SELECT * FROM employees WHERE salary BETWEEN 4000 AND 6000;

-- 多条件组合
SELECT * FROM employees
WHERE department_id = 10
  AND status = 'active'
  AND salary > 5000;

-- OR 条件
SELECT * FROM employees
WHERE department_id = 10 OR department_id = 20;

-- IN 查询
SELECT * FROM employees
WHERE department_id IN (10, 20, 30);

1.3 去重查询 ​

sql
-- 查询所有不同的部门 ID
SELECT DISTINCT department_id FROM employees;

-- 查询不同的部门和状态组合
SELECT DISTINCT department_id, status FROM employees;

DISTINCT 底层原理：

  • MySQL 通过临时表实现 DISTINCT 去重
  • 优化器会根据索引情况选择排序或使用哈希表
  • 在结果集较大时，DISTINCT 会增加内存和 CPU 消耗

1.4 排序查询 ​

sql
-- 单字段排序
SELECT * FROM employees ORDER BY salary DESC;

-- 多字段排序
SELECT * FROM employees
ORDER BY department_id ASC, salary DESC;

-- 使用表达式排序
SELECT * FROM employees
ORDER BY salary * 12 DESC;

1.5 分页查询 ​

sql
-- 获取前 10 条
SELECT * FROM employees LIMIT 10;

-- 从第 11 条开始，获取 10 条（第 2 页）
SELECT * FROM employees LIMIT 10, 10;

-- 标准语法（MySQL 8.0+）
SELECT * FROM employees LIMIT 10 OFFSET 10;

分页性能优化：

sql
-- 传统分页（深分页性能差）
SELECT * FROM orders LIMIT 100000, 10;

-- 优化方案：子查询先获取主键
SELECT * FROM orders
WHERE id IN (
    SELECT id FROM orders
    ORDER BY id LIMIT 100000, 10
);

-- 更好的方案：游标分页（已知上一页最后一条的 ID）
SELECT * FROM orders WHERE id > 100000 ORDER BY id LIMIT 10;

1.6 聚合查询 ​

sql
-- 统计函数
SELECT
    COUNT(*) AS '总人数',
    COUNT(email) AS '有邮箱人数',
    AVG(salary) AS '平均薪资',
    MAX(salary) AS '最高薪资',
    MIN(salary) AS '最低薪资',
    SUM(salary) AS '薪资总额'
FROM employees
WHERE status = 'active';

聚合函数说明：

  • COUNT(*)：统计总行数，包括 NULL
  • COUNT(column)：统计指定列非 NULL 的行数
  • AVG()：平均值，忽略 NULL
  • SUM()：求和，忽略 NULL
  • MAX() / MIN()：最大/最小值，忽略 NULL

二、多表连接查询 ​

2.1 连接查询概述 ​

连接查询（JOIN）用于根据两张或多张表之间的关联关系，从这些表中检索数据。

连接的类型：

  • INNER JOIN（内连接）
  • LEFT JOIN（左连接）
  • RIGHT JOIN（右连接）
  • FULL OUTER JOIN（全连接）
  • CROSS JOIN（交叉连接）
  • SELF JOIN（自连接）

示例表结构：

sql
-- 部门表
CREATE TABLE departments (
    id INT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(100) NOT NULL,
    location VARCHAR(100)
);

-- 员工表
CREATE TABLE employees (
    id INT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(100) NOT NULL,
    department_id INT,
    salary DECIMAL(10, 2),
    manager_id INT,
    FOREIGN KEY (department_id) REFERENCES departments(id)
);

-- 插入测试数据
INSERT INTO departments VALUES
(1, '工程部', '北京'),
(2, '销售部', '上海'),
(3, '市场部', '广州'),
(4, '财务部', '深圳'),
(5, '人力资源部', '成都');

INSERT INTO employees VALUES
(1, '张三', 1, 8000, NULL),
(2, '李四', 1, 7500, 1),
(3, '王五', 2, 6500, NULL),
(4, '赵六', 2, 6000, 3),
(5, '钱七', 3, 7000, NULL),
(6, '孙八', 4, 5500, NULL),
(7, '周九', NULL, 9000, NULL),
(8, '吴十', NULL, 12000, 7);

2.2 INNER JOIN 内连接 ​

内连接只返回两表中匹配的行。

sql
-- 基本内连接
SELECT e.id, e.name, e.salary, d.name AS department_name
FROM employees e
INNER JOIN departments d ON e.department_id = d.id;

执行结果：

2李四7500工程部
3王五6500销售部
4赵六6000销售部
5钱七7000市场部
6孙八5500财务部

张三和吴十（department_id 为 NULL）不被返回。

多表内连接：

sql
SELECT e.name, d.name AS department_name, p.name AS project_name
FROM employees e
INNER JOIN departments d ON e.department_id = d.id
INNER JOIN projects p ON d.id = p.department_id;

等值连接 vs 自然连接：

sql
-- 等值连接（显式 ON 条件）
SELECT e.*, d.* FROM employees e INNER JOIN departments d ON e.department_id = d.id;

-- 使用 USING 简化（连接列名相同时）
SELECT e.*, d.* FROM employees e INNER JOIN departments d USING (department_id);

2.3 LEFT JOIN 左连接 ​

左连接返回左表的所有行，即使右表没有匹配。

sql
-- 左连接：返回所有员工，包括没有部门的
SELECT e.id, e.name, e.salary, d.name AS department_name
FROM employees e
LEFT JOIN departments d ON e.department_id = d.id;

周九和吴十没有匹配的部门，department_name 显示为 NULL。

2.4 RIGHT JOIN 右连接 ​

右连接返回右表的所有行，即使左表没有匹配。

sql
-- 右连接：返回所有部门，包括没有员工的
SELECT e.id, e.name, d.name AS department_name, d.location
FROM employees e
RIGHT JOIN departments d ON e.department_id = d.id;

执行结果：

2.5 FULL OUTER JOIN 全连接 ​

全连接返回两表的所有行，无论是否匹配。

sql
-- MySQL 不直接支持 FULL OUTER JOIN
-- 使用 UNION 模拟
SELECT e.id, e.name, d.name AS department_name
FROM employees e
LEFT JOIN departments d ON e.department_id = d.id
UNION
SELECT e.id, e.name, d.name AS department_name
FROM employees e
RIGHT JOIN departments d ON e.department_id = d.id;

2.6 CROSS JOIN 交叉连接 ​

交叉连接返回两表的笛卡尔积（每一行与另一表的每一行组合）。

sql
-- 交叉连接（笛卡尔积）
SELECT e.name, d.name
FROM employees e
CROSS JOIN departments d;

-- 等价写法
SELECT e.name, d.name
FROM employees e, departments d;

注意：交叉连接在实际应用中很少使用，通常用于生成测试数据或日历表。

2.7 SELF JOIN 自连接 ​

自连接是表与自身的连接，用于表中自关联的场景（如员工与上级的关系）。

sql
-- 查询每个员工及其上级
SELECT
    e.name AS employee_name,
    m.name AS manager_name
FROM employees e
LEFT JOIN employees m ON e.manager_id = m.id;

执行结果：

2.8 连接查询的底层原理 ​

MySQL 连接算法：

  1. Nested Loop Join（嵌套循环连接）：

    • 最基本的连接算法
    • 外层表的每一行与内层表进行匹配
    • 时间复杂度：O(n × m)

  2. Block Nested Loop Join（块嵌套循环连接）：

    • 将外层表的行缓存到 join_buffer 中
    • 批量与内层表比较
    • 减少磁盘 I/O 次数

  3. Index Nested Loop Join（索引嵌套循环连接）：

    • 内层表有可用索引
    • 外层表每行通过索引查找内层表
    • 时间复杂度：O(n × log m)

优化建议：

  • 小表作为驱动表（LEFT JOIN 时左表为驱动表）
  • 连接条件上建立索引
  • 避免不必要的 JOIN 列（使用 SELECT 指定列）
  • 合理使用 STRAIGHT_JOIN 控制驱动表顺序

三、子查询 ​

3.1 子查询概述 ​

子查询是指嵌套在另一个 SQL 语句中的 SELECT 语句。子查询可以出现在 WHERE、FROM、SELECT 等子句中。

子查询的分类：

  • WHERE 子查询：出现在 WHERE 子句中
  • FROM 子查询：出现在 FROM 子句中（又称为派生表）
  • SELECT 子查询：出现在 SELECT 子句中
  • HAVING 子查询：出现在 HAVING 子句中

相关子查询与非相关子查询：

  • 非相关子查询：子查询独立执行，结果用于外层查询
  • 相关子查询：子查询依赖外层查询的值，需要逐行执行

3.2 WHERE 子查询 ​

WHERE 子查询出现在 WHERE 子句中，用于过滤数据。

使用 IN 运算符：

sql
-- 查询工程部和销售部的所有员工
SELECT * FROM employees
WHERE department_id IN (
    SELECT id FROM departments WHERE name IN ('工程部', '销售部')
);

使用 EXISTS 运算符：

sql
-- 查询有项目的部门
SELECT * FROM departments d
WHERE EXISTS (
    SELECT 1 FROM projects p WHERE p.department_id = d.id
);

使用比较运算符：

sql
-- 查询薪资高于平均薪资的员工
SELECT * FROM employees
WHERE salary > (
    SELECT AVG(salary) FROM employees
);

-- 查询薪资高于所在部门平均薪资的员工（相关子查询）
SELECT * FROM employees e
WHERE salary > (
    SELECT AVG(salary)
    FROM employees
    WHERE department_id = e.department_id
);

使用 ANY / ALL：

sql
-- 查询薪资高于任何工程部员工的员工
SELECT * FROM employees
WHERE salary > ANY (
    SELECT salary FROM employees WHERE department_id = 1
);

-- 查询薪资高于所有工程部员工的员工
SELECT * FROM employees
WHERE salary > ALL (
    SELECT salary FROM employees WHERE department_id = 1
);

3.3 FROM 子查询 ​

FROM 子查询将子查询的结果作为临时表使用，又称为派生表（Derived Table）。

sql
-- 查询每个部门的平均薪资和员工人数
SELECT
    d.name AS department_name,
    dept_stats.avg_salary,
    dept_stats.employee_count
FROM departments d
INNER JOIN (
    SELECT
        department_id,
        AVG(salary) AS avg_salary,
        COUNT(*) AS employee_count
    FROM employees
    WHERE department_id IS NOT NULL
    GROUP BY department_id
) AS dept_stats ON d.id = dept_stats.department_id
WHERE dept_stats.avg_salary > 6000;

派生表的要求：

  • 必须使用别名
  • 可以与其他表进行 JOIN 操作
  • MySQL 优化器会尽量将派生表合并到外层查询（MySQL 8.0+）

3.4 SELECT 子查询 ​

SELECT 子查询出现在 SELECT 子句中，为每行生成一个计算值。

sql
-- 查询每个员工及其部门的平均薪资
SELECT
    e.name,
    e.salary,
    e.salary / (
        SELECT AVG(salary) FROM employees WHERE department_id = e.department_id
    ) AS salary_ratio
FROM employees e;

3.5 HAVING 子查询 ​

sql
-- 查询平均薪资高于公司平均水平的部门
SELECT
    d.name,
    AVG(e.salary) AS avg_salary
FROM departments d
JOIN employees e ON d.id = e.department_id
GROUP BY d.id, d.name
HAVING AVG(e.salary) > (
    SELECT AVG(salary) FROM employees
);

3.6 子查询优化 ​

优化策略：

  1. 使用 JOIN 替代子查询：在很多场景下，JOIN 比子查询更高效
  2. 使用 EXISTS 替代 IN：EXISTS 在检测到第一个匹配后即停止
  3. 保证子查询列有索引：子查询的 WHERE 条件列应建立索引
  4. 避免在子查询中使用 LIMIT：某些情况下 MySQL 无法优化
sql
-- 子查询方式
SELECT * FROM employees
WHERE department_id IN (SELECT id FROM departments WHERE name = '工程部');

-- JOIN 方式（更高效）
SELECT e.* FROM employees e
JOIN departments d ON e.department_id = d.id
WHERE d.name = '工程部';

四、分组与聚合 ​

4.1 GROUP BY 基础 ​

GROUP BY 将数据按一个或多个列分组，通常与聚合函数配合使用。

sql
-- 按部门分组统计
SELECT
    department_id,
    COUNT(*) AS employee_count,
    AVG(salary) AS avg_salary,
    MAX(salary) AS max_salary,
    MIN(salary) AS min_salary
FROM employees
WHERE department_id IS NOT NULL
GROUP BY department_id;

4.2 多列分组 ​

sql
-- 按部门和状态分组
SELECT
    department_id,
    status,
    COUNT(*) AS employee_count,
    AVG(salary) AS avg_salary
FROM employees
GROUP BY department_id, status;

4.3 GROUP BY 的注意事项 ​

ONLY_FULL_GROUP_BY 模式：

MySQL 默认开启 ONLY_FULL_GROUP_BY 模式，要求 SELECT 中的非聚合列必须出现在 GROUP BY 中。

sql
-- 错误：name 没有出现在 GROUP BY 中
SELECT department_id, name, AVG(salary)
FROM employees
GROUP BY department_id;

-- 正确
SELECT department_id, name, AVG(salary)
FROM employees
GROUP BY department_id, name;

关闭 ONLY_FULL_GROUP_BY（不推荐）：

sql
SET SESSION sql_mode = (SELECT REPLACE(@@sql_mode, 'ONLY_FULL_GROUP_BY', ''));

4.4 HAVING 子句 ​

HAVING 子句用于对分组后的结果进行过滤（作用于分组而非行）。

sql
-- 查询平均薪资大于 6000 的部门
SELECT
    department_id,
    AVG(salary) AS avg_salary,
    COUNT(*) AS employee_count
FROM employees
WHERE salary > 5000
GROUP BY department_id
HAVING AVG(salary) > 6000;

WHERE vs HAVING：

对比项WHEREHAVING
作用对象行分组
执行时机GROUP BY 之前GROUP BY 之后
能否用聚合函数不能能
能否用列别名能取决于 MySQL 版本

4.5 聚合函数 ​

MySQL 支持的聚合函数：

sql
-- COUNT：计数
SELECT COUNT(*) FROM employees;
SELECT COUNT(DISTINCT department_id) FROM employees;

-- SUM：求和
SELECT SUM(salary) FROM employees WHERE department_id = 1;

-- AVG：平均值
SELECT AVG(salary) FROM employees;

-- MAX / MIN：最大/最小值
SELECT MAX(salary), MIN(salary) FROM employees;

-- GROUP_CONCAT：将分组内的值连接成字符串
SELECT
    department_id,
    GROUP_CONCAT(name ORDER BY salary DESC SEPARATOR ', ') AS employees
FROM employees
WHERE department_id IS NOT NULL
GROUP BY department_id;

4.6 ROLLUP 和 CUBE（MySQL 8.0+） ​

WITH ROLLUP：生成分组小计和总计。

sql
SELECT
    department_id,
    status,
    SUM(salary) AS total_salary
FROM employees
GROUP BY department_id, status WITH ROLLUP;

执行结果示例：

department_idstatustotal_salary
1active15500
1NULL15500
2active12500
2NULL12500
NULLNULL28000

WITH CUBE：生成所有可能的分组组合（MySQL 8.0 中需通过 GROUPING 函数配合实现）。

4.7 窗口函数（MySQL 8.0+） ​

窗口函数可以在查询结果的相关行上执行计算，而不需要将数据分组为单行。

sql
-- 计算每个部门内员工的薪资排名
SELECT
    name,
    department_id,
    salary,
    RANK() OVER (PARTITION BY department_id ORDER BY salary DESC) AS dept_rank,
    ROW_NUMBER() OVER (PARTITION BY department_id ORDER BY salary DESC) AS row_num,
    DENSE_RANK() OVER (PARTITION BY department_id ORDER BY salary DESC) AS dense_rank
FROM employees;

常用窗口函数：

sql
-- 排名函数
ROW_NUMBER() OVER (ORDER BY salary DESC)     -- 唯一排名（1, 2, 3, 4）
RANK() OVER (ORDER BY salary DESC)           -- 并列排名（1, 2, 2, 4）
DENSE_RANK() OVER (ORDER BY salary DESC)     -- 紧密排名（1, 2, 2, 3）
NTILE(4) OVER (ORDER BY salary DESC)         -- 分桶

-- 偏移函数
LAG(salary, 1) OVER (ORDER BY id)            -- 上一行的值
LEAD(salary, 1) OVER (ORDER BY id)           -- 下一行的值
FIRST_VALUE(name) OVER (PARTITION BY dept ORDER BY salary DESC)  -- 分组第一个值
LAST_VALUE(name) OVER (PARTITION BY dept ORDER BY salary DESC)   -- 分组最后一个值

-- 聚合窗口函数
SUM(salary) OVER (ORDER BY id ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)  -- 累计和
AVG(salary) OVER (PARTITION BY department_id)  -- 分组平均
COUNT(*) OVER (PARTITION BY department_id)      -- 分组计数

五、集合操作 ​

5.1 UNION 与 UNION ALL ​

集合操作用于合并两个或多个 SELECT 语句的结果集。

UNION：合并结果集并去除重复行。

sql
-- 查询工程部员工和销售部员工
SELECT name, salary FROM employees WHERE department_id = 1
UNION
SELECT name, salary FROM employees WHERE department_id = 2;

UNION ALL：合并结果集但不去重，性能优于 UNION。

sql
-- 查询所有员工（包括没有部门的）和部门信息
SELECT name AS '名称', '员工' AS '类型' FROM employees
UNION ALL
SELECT name, '部门' FROM departments;

5.2 UNION vs UNION ALL ​

对比项UNIONUNION ALL
去重是否
性能较慢（需要排序去重）较快
重复数据被移除保留
适用场景需要去重不需要去重

选择建议：如果确定不会有重复数据，使用 UNION ALL 以获得更好的性能。

5.3 集合操作的规则 ​

  1. 列数必须相同：所有 SELECT 语句的列数必须一致
  2. 列类型必须兼容：对应列的数据类型必须可以隐式转换
  3. 列名以第一个 SELECT 为准：结果集的列名来自第一个 SELECT 语句
  4. ORDER BY 必须放在最后：只能对最终结果集排序
sql
-- 正确的集合操作
SELECT id, name, salary FROM employees WHERE salary > 8000
UNION ALL
SELECT id, name, salary FROM employees WHERE department_id = 1
ORDER BY salary DESC;

-- 错误：ORDER BY 放在中间
SELECT id, name, salary FROM employees WHERE salary > 8000 ORDER BY salary
UNION ALL
SELECT id, name, salary FROM employees WHERE department_id = 1;

5.4 集合操作的应用场景 ​

sql
-- 多表结构相同的数据合并
SELECT name, email, 'active' AS status FROM employees WHERE status = 'active'
UNION ALL
SELECT name, email, 'resigned' AS status FROM employees_archive;

-- 对比两个时期的数据差异
-- 在一个查询中生成多维度的统计报表
SELECT '工程部' AS department_name, AVG(salary) AS avg_salary
FROM employees WHERE department_id = 1
UNION ALL
SELECT '销售部', AVG(salary) FROM employees WHERE department_id = 2
UNION ALL
SELECT '市场部', AVG(salary) FROM employees WHERE department_id = 3;

六、视图的创建与使用 ​

6.1 视图概述 ​

视图（View）是基于 SELECT 查询结果的虚拟表。视图本身不存储数据，数据来自其依赖的基表。

视图的特点：

  • 视图是 SQL 语句的封装，简化复杂查询
  • 视图可以像表一样使用（SELECT、INSERT、UPDATE、DELETE 视情况而定）
  • 视图提供了数据安全机制，限制用户只能访问特定数据
  • 视图的更新受限于其定义的复杂性

6.2 创建视图 ​

sql
CREATE [OR REPLACE] [ALGORITHM = algorithm]
VIEW view_name [(column_list)]
AS select_statement
[WITH [CASCADED | LOCAL] CHECK OPTION];

参数说明：

  • OR REPLACE：如果视图已存在，替换之
  • ALGORITHM：视图的处理算法
    • UNDEFINED：由 MySQL 自动选择（默认）
    • MERGE：将视图的查询合并到外层查询中
    • TEMPTABLE：先将视图结果存储到临时表
  • CHECK OPTION：限制通过视图的更新操作
    • CASCADED：级联检查所有依赖视图（默认）
    • LOCAL：只检查当前视图

6.3 创建示例 ​

sql
-- 简单视图：查询活跃员工
CREATE OR REPLACE VIEW active_employees AS
SELECT id, name, email, salary, department_id
FROM employees
WHERE status = 'active';

-- 使用视图
SELECT * FROM active_employees WHERE salary > 6000;

-- 带列名的视图
CREATE VIEW dept_summary (dept_id, dept_name, emp_count, avg_salary) AS
SELECT
    d.id,
    d.name,
    COUNT(e.id),
    AVG(e.salary)
FROM departments d
LEFT JOIN employees e ON d.id = e.department_id
GROUP BY d.id, d.name;

6.4 视图的更新 ​

可更新视图的条件：

  • 只涉及一张表
  • 不包含聚合函数（SUM、AVG、COUNT 等）
  • 不包含 GROUP BY、DISTINCT、HAVING
  • 不包含子查询
  • 不包含 UNION 或 UNION ALL
sql
-- 创建可更新的视图
CREATE VIEW high_salary_employees AS
SELECT id, name, salary
FROM employees
WHERE salary > 8000;

-- 通过视图更新数据
UPDATE high_salary_employees SET salary = 9000 WHERE id = 1;
-- 等价于：UPDATE employees SET salary = 9000 WHERE id = 1 AND salary > 8000;

-- 插入数据（受 CHECK OPTION 限制）
INSERT INTO high_salary_employees (id, name, salary) VALUES (99, '新员工', 8500);
-- 如果使用了 WITH CHECK OPTION，且 salary <= 8000 则会报错

6.5 视图的优势与局限 ​

优势：

  • 安全性：限制用户访问特定列和行
  • 简化查询：封装复杂的 JOIN、子查询
  • 逻辑独立性：基表结构变更时，可通过视图屏蔽影响
  • 自定义数据：提供不同的数据视角

局限：

  • 性能：复杂视图可能导致性能下降
  • 更新限制：不是所有视图都可以更新
  • 排序限制：某些视图不支持 ORDER BY
  • 物化视图：MySQL 不支持真正的物化视图（可使用表 + 触发器模拟）

6.6 管理视图 ​

sql
-- 查看所有视图
SHOW FULL TABLES WHERE table_type = 'VIEW';

-- 查看视图定义
SHOW CREATE VIEW view_name;

-- 查看视图结构
DESCRIBE view_name;

-- 删除视图
DROP VIEW [IF EXISTS] view_name;

-- 修改视图
ALTER VIEW view_name AS SELECT ...;

七、存储过程基础 ​

7.1 存储过程概述 ​

存储过程（Stored Procedure）是一组为了完成特定功能的 SQL 语句集合，经编译后存储在数据库中。

存储过程的优势：

  • 性能：编译后执行，减少网络传输
  • 安全：控制数据访问权限
  • 复用：一次编写，多次使用
  • 复杂逻辑：支持条件、循环等编程逻辑

存储过程的局限：

  • 可移植性差：不同数据库语法不同
  • 调试困难：MySQL 的调试功能有限
  • 版本管理困难：存储过程存储在数据库中

7.2 创建存储过程 ​

sql
CREATE [DEFINER = user] PROCEDURE procedure_name
    ([IN | OUT | INOUT] param_name param_type [, ...])
[character string ...]
BEGIN
    routine_body
END;

参数类型：

  • IN：输入参数，调用方传递值给存储过程
  • OUT：输出参数，存储过程将值传递回调用方
  • INOUT：既能输入又能输出

7.3 创建示例 ​

sql
-- 计算员工年薪的存储过程
DELIMITER //

CREATE PROCEDURE calculate_annual_salary(
    IN emp_id INT,
    OUT annual_salary DECIMAL(12, 2)
)
BEGIN
    SELECT salary * 12 INTO annual_salary
    FROM employees WHERE id = emp_id;
END //

DELIMITER ;

DELIMITER 的作用： 存储过程内部的 SQL 语句以分号 ; 结尾，而分号也是 MySQL 命令行的默认分隔符。使用 DELIMITER // 将分隔符改为 //，避免冲突。

7.4 调用存储过程 ​

sql
-- 调用存储过程
CALL calculate_annual_salary(1, @annual_salary);

-- 查看结果
SELECT @annual_salary;

7.5 复杂存储过程示例 ​

sql
DELIMITER //

CREATE PROCEDURE transfer_salary(
    IN from_emp_id INT,
    IN to_emp_id INT,
    IN transfer_amount DECIMAL(10, 2)
)
BEGIN
    DECLARE current_salary DECIMAL(10, 2);
    DECLARE EXIT HANDLER FOR SQLEXCEPTION
    BEGIN
        ROLLBACK;
        RESIGNAL;
    END;

    START TRANSACTION;

    SELECT salary INTO current_salary FROM employees WHERE id = from_emp_id FOR UPDATE;

    IF current_salary < transfer_amount THEN
        SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = '薪资不足，转账失败';
    END IF;

    UPDATE employees SET salary = salary - transfer_amount WHERE id = from_emp_id;
    UPDATE employees SET salary = salary + transfer_amount WHERE id = to_emp_id;

    COMMIT;
END //

DELIMITER ;

7.6 存储过程中的编程元素 ​

sql
-- 变量声明
DECLARE variable_name data_type [DEFAULT value];

-- 赋值
SET variable_name = value;
SELECT column INTO variable_name FROM table WHERE ...;

-- 条件语句
IF condition THEN
    statement1;
ELSEIF condition THEN
    statement2;
ELSE
    statement3;
END IF;

-- 循环语句（WHILE）
WHILE condition DO
    statement;
END WHILE;

-- 循环语句（REPEAT）
REPEAT
    statement;
UNTIL condition
END REPEAT;

-- 循环语句（LOOP）
loop_label: LOOP
    IF condition THEN
        LEAVE loop_label;
    END IF;
    ITERATE loop_label;  -- 跳过本次循环
END LOOP;

-- 游标
DECLARE cursor_name CURSOR FOR SELECT_statement;
DECLARE CONTINUE HANDLER FOR NOT FOUND SET done = 1;
OPEN cursor_name;
read_loop: LOOP
    FETCH cursor_name INTO variable1, variable2;
    IF done THEN LEAVE read_loop; END IF;
    -- 处理逻辑
END LOOP;
CLOSE cursor_name;

sql

-- 查看存储过程定义
SHOW CREATE PROCEDURE procedure_name;

-- 查看存储过程参数
SHOW PROCEDURE STATUS WHERE Db = 'database_name';

-- 删除存储过程

-- 修改存储过程

八、触发器基础 ​

8.1 触发器概述 ​

触发器（Trigger）是与表相关联的特殊存储过程，当特定事件发生时自动执行。

触发器的特点：

  • 自动执行，无需手动调用
  • 与表绑定，当表上发生 INSERT、UPDATE、DELETE 时触发
  • 可以访问触发事件前后的行数据（OLD 和 NEW）

触发器的类型：

  • INSERT 触发器：在 INSERT 事件时触发
  • UPDATE 触发器：在 UPDATE 事件时触发
  • DELETE 触发器：在 DELETE 事件时触发

每个表每个事件最多可以有一个 BEFORE 触发器和一个 AFTER 触发器。

8.2 创建触发器 ​

sql
CREATE [DEFINER = user] TRIGGER trigger_name
    {BEFORE | AFTER} {INSERT | UPDATE | DELETE}
    ON table_name
    FOR EACH ROW
    [trigger_order]
    BEGIN
        trigger_body
    END;

关键概念：

  • BEFORE：在事件之前触发，可以修改即将插入/更新的数据
  • AFTER：在事件之后触发，用于记录日志或执行后续操作
  • FOR EACH ROW：行级触发器，每一行都触发一次
  • OLD：引用变更前的行（DELETE 和 UPDATE）
  • NEW：引用变更后的行（INSERT 和 UPDATE）

8.3 INSERT 触发器示例 ​

sql
DELIMITER //

-- 自动记录创建时间
CREATE TRIGGER employees_before_insert
BEFORE INSERT ON employees
FOR EACH ROW
BEGIN
    IF NEW.created_at IS NULL THEN
        SET NEW.created_at = NOW();
    END IF;
    IF NEW.updated_at IS NULL THEN
        SET NEW.updated_at = NOW();
    END IF;
END //

DELIMITER ;

8.4 UPDATE 触发器示例 ​

sql
DELIMITER //

-- 记录薪资变更日志
CREATE TABLE salary_log (
    id INT AUTO_INCREMENT PRIMARY KEY,
    employee_id INT NOT NULL,
    old_salary DECIMAL(10, 2),
    new_salary DECIMAL(10, 2),
    changed_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    changed_by VARCHAR(50)
);

CREATE TRIGGER employees_after_update_salary
AFTER UPDATE ON employees
FOR EACH ROW
BEGIN
    IF NEW.salary != OLD.salary THEN
        INSERT INTO salary_log (employee_id, old_salary, new_salary)
        VALUES (OLD.id, OLD.salary, NEW.salary);
    END IF;
END //

DELIMITER ;

8.5 DELETE 触发器示例 ​

sql
DELIMITER //

-- 防止删除关键员工
CREATE TRIGGER employees_before_delete
BEFORE DELETE ON employees
FOR EACH ROW
BEGIN
    IF OLD.salary > 10000 THEN
        SIGNAL SQLSTATE '45000'
            SET MESSAGE_TEXT = '薪资超过10000的员工不能删除';
    END IF;

    INSERT INTO employees_archive
        (id, name, email, salary, deleted_at)
    VALUES
        (OLD.id, OLD.name, OLD.email, OLD.salary, NOW());
END //

DELIMITER ;

8.6 触发器的实际应用 ​

sql
-- 数据审计：记录所有变更
DELIMITER //

CREATE TABLE audit_log (
    id INT AUTO_INCREMENT PRIMARY KEY,
    table_name VARCHAR(50),
    action VARCHAR(10),  -- INSERT, UPDATE, DELETE
    record_id INT,
    old_data JSON,
    new_data JSON,
    changed_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    changed_by VARCHAR(50)
);

CREATE TRIGGER audit_employees_insert
AFTER INSERT ON employees
FOR EACH ROW
BEGIN
    INSERT INTO audit_log (table_name, action, record_id, new_data)
    VALUES ('employees', 'INSERT', NEW.id,
            JSON_OBJECT('id', NEW.id, 'name', NEW.name, 'salary', NEW.salary));
END //

CREATE TRIGGER audit_employees_update
AFTER UPDATE ON employees
FOR EACH ROW
BEGIN
    INSERT INTO audit_log (table_name, action, record_id, old_data, new_data)
    VALUES ('employees', 'UPDATE', NEW.id,
            JSON_OBJECT('id', OLD.id, 'name', OLD.name, 'salary', OLD.salary),
            JSON_OBJECT('id', NEW.id, 'name', NEW.name, 'salary', NEW.salary));
END //

DELIMITER ;

8.7 触发器的优缺点 ​

优点：

  • 自动执行，减少应用层代码
  • 数据完整性保障
  • 审计和日志记录

缺点：

  • 增加系统开销
  • 难以调试和维护
  • 逻辑分散在数据库中
  • 不支持复杂的错误处理
  • 递归触发器可能导致无限循环（MySQL 默认禁用）

-- 查看触发器定义
SHOW CREATE TRIGGER trigger_name;

-- 删除触发器
DROP TRIGGER [IF EXISTS] trigger_name;

-- 修改触发器（必须先删除再创建）

九、权限管理基础 ​

9.1 用户管理 ​

sql
-- 创建用户
CREATE USER 'username'@'host' IDENTIFIED BY 'password';

-- 创建用户并指定资源限制
CREATE USER 'app_user'@'%'
    IDENTIFIED BY 'StrongPassword123!'
    WITH MAX_CONNECTIONS_PER_HOUR 100
         MAX_UPDATES_PER_HOUR 1000
         MAX_QUERIES_PER_HOUR 1000;

-- 修改用户密码
ALTER USER 'username'@'host' IDENTIFIED BY 'new_password';

-- 重命名用户
RENAME USER 'old_user'@'host' TO 'new_user'@'host';

-- 删除用户
DROP USER 'username'@'host';

-- 查看当前用户
SELECT CURRENT_USER();

host 参数说明：

  • 'localhost'：只能本地登录
  • '%'：允许从任何主机登录
  • '192.168.1.%'：允许从特定网段登录
  • '192.168.1.100'：只允许从特定 IP 登录

9.2 权限类型 ​

全局权限：适用于所有数据库。

sql
GRANT SELECT ON *.* TO 'user'@'host';
GRANT ALL PRIVILEGES ON *.* TO 'user'@'host';

数据库级权限：适用于特定数据库的所有表。

sql
GRANT SELECT, INSERT, UPDATE, DELETE ON mydb.* TO 'user'@'host';

表级权限：适用于特定表。

sql
GRANT SELECT (id, name), INSERT ON mydb.employees TO 'user'@'host';

列级权限：适用于特定列。

sql
GRANT SELECT (id, name, salary) ON mydb.employees TO 'user'@'host';

存储过程权限：

sql
GRANT EXECUTE ON PROCEDURE mydb.procedure_name TO 'user'@'host';

9.3 常用权限列表 ​

权限说明层级
SELECT查询数据表/列
INSERT插入数据表
UPDATE更新数据表/列
DELETE删除数据表
CREATE创建数据库/表库
DROP删除数据库/表库/表
ALTER修改表结构表
INDEX创建/删除索引表
REFERENCES创建外键表
CREATE TEMPORARY TABLES创建临时表库
LOCK TABLES锁定表库
EXECUTE执行存储过程库
CREATE VIEW创建视图库
SHOW VIEW查看视图库
CREATE ROUTINE创建存储过程/函数库
ALL PRIVILEGES所有权限全局

9.4 授权与撤销 ​

sql
-- 授权
GRANT SELECT, INSERT, UPDATE ON shop.* TO 'app_user'@'localhost';

-- 授予所有权限
GRANT ALL PRIVILEGES ON shop.* TO 'admin_user'@'localhost';

-- 撤销权限
REVOKE DELETE ON shop.* FROM 'app_user'@'localhost';

-- 撤销所有权限
REVOKE ALL PRIVILEGES ON shop.* FROM 'user'@'host';

-- 刷新权限表
FLUSH PRIVILEGES;

9.5 角色管理（MySQL 8.0+） ​

角色是一组权限的集合，可以授予用户。

sql
-- 创建角色
CREATE ROLE 'read_only', 'app_developer', 'app_admin';

-- 为角色授予权限
GRANT SELECT ON shop.* TO 'read_only';
GRANT SELECT, INSERT, UPDATE, DELETE ON shop.* TO 'app_developer';
GRANT ALL PRIVILEGES ON shop.* TO 'app_admin';

-- 将角色授予用户
GRANT 'read_only' TO 'viewer'@'localhost';
GRANT 'app_developer' TO 'dev_user'@'localhost';

-- 设置默认角色
SET DEFAULT ROLE 'app_developer' TO 'dev_user'@'localhost';

-- 当前会话启用角色
SET ROLE ALL;

-- 查看角色
SELECT * FROM mysql.role_edges;

-- 撤销角色
REVOKE 'read_only' FROM 'viewer'@'localhost';

-- 删除角色
DROP ROLE 'read_only';

9.6 权限检查流程 ​

MySQL 的权限检查遵循以下层级：

1. 全局权限（*.*）：检查用户是否有相应的全局权限
2. 数据库权限（db.*）：检查用户是否有该数据库的权限
3. 表权限（db.table）：检查用户是否有该表的权限
4. 列权限（db.table.column）：检查用户是否有该列的权限
5. 存储过程权限：检查用户是否有该存储过程的权限

权限检查的特点：

  • 每次查询都要检查权限（性能开销）
  • 权限表存储在 mysql 数据库中
  • 权限变更后通过 FLUSH PRIVILEGES 生效
  • MySQL 8.0 中，授权表已从 mysql.user 等迁移到数据字典

9.7 安全最佳实践 ​

  1. 最小权限原则：用户只获得完成其工作所需的最少权限
  2. 避免使用 root：为每个应用创建独立的数据库用户
  3. 强密码策略：使用至少 12 位包含大小写字母、数字和特殊字符的密码
  4. 限制主机访问：使用 'localhost' 或特定 IP 而非 '%'
  5. 定期审计权限：检查并移除不再需要的权限
  6. 禁用远程 root 登录：确保 root 只能本地访问
  7. 使用 SSL 连接：加密客户端与服务端的通信
sql
-- 安全的用户创建示例
CREATE USER 'app_user'@'localhost'
    IDENTIFIED BY 'ComplexP@ss2024!'
    REQUIRE SSL
    WITH MAX_CONNECTIONS_PER_HOUR 50;

GRANT SELECT, INSERT, UPDATE, DELETE ON shop.* TO 'app_user'@'localhost';

-- 确保 root 只能本地访问
DELETE FROM mysql.user WHERE User = 'root' AND Host NOT IN ('localhost', '127.0.0.1', '::1');
FLUSH PRIVILEGES;
